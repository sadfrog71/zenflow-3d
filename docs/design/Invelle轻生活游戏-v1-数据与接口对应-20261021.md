## 1. 契约来源与兼容规则

浏览器／App 经网关使用 `/api/zenflow/v1`，Controller 使用 `/zenflow/v1`；下表省略该前缀。管理员使用 `/api/zenflow-admin/v1`，不共用消费者令牌。静态场景资源与私人业务接口分开，URL 仅在发布后填入清单。

已有依据：`src/core/zenflow/session.ts`、`core.ts`、`community.ts`，以及服务端 identity、books、capsule、conversation、community 下的 Controller。旧[接口契约 v0.3](../接口契约-v0.3.md)中未实现的 multipart parts／媒体 stream／转写任务仅为历史预留；本专题首版采用整文件受限上传 `/media/uploads/{id}/content` 与播放 `/media/{id}/content`。不同时实现两套路径，也不据此移除任何已经运行的旧接口；G00 再核对源码变化。

现有返回格式混合：部分为 `R<T>`，部分直接 DTO；`session.request` 已兼容两类。新增 JSON 业务端点统一 `R<T>`，成功 `code=0,data=...`，错误 `data.errorCode`；既有端点不强制改包裹。二进制／SSE 单独解析。统一 Adapter 需保留 HTTP 状态、errorCode、requestId、Retry-After 与取消原因；现有仅抛字符串 Error 不够支撑重试分类，须定向扩展。禁止令二进制内容经过现有 JSON.stringify 请求函数。

业务 ID 一律字符串，版本为安全整数，时间为服务端 UTC ISO 8601；界面再按时区显示。公开 DTO 只含允许字段。资源所有者永远来自受信 tenant＋APP_USER＋userId，不接收请求中的 owner 作为鉴权依据。新字段在服务端严格校验；非空、枚举、长度、数量与版本约束同时覆盖前端提示及服务端拒绝。

## 3. 主要数据对象与字段归属

| 对象 | 服务端权威字段 | 只在本机或运行时 | 关键约束 |
| --- | --- | --- | --- |
| GardenState | gardenId、stateVersion、sceneVersion、fish、placements、environment、updatedAt | localRevision、baseVersion、pendingOps、相机姿态 | 一主体一份；sceneVersion 表示兼容资产版本，不接受任意 URL |
| Fish | instanceId、archetypeId、name | 位置、速度、喂食动画 | ID 稳定；不保存饥饿值／收益；名称长度由集中限制定义 |
| Placement | instanceId、archetypeId、anchorId、transform | previewTransform、选中状态 | transform 使用经版本定义的锚点局部坐标，有限范围及合法数值；客户端不能添任意模型 |
| Environment | presetId、lampEnabled | 预览、粒子状态、质量、音量、reducedMotion | 六个首版值；缺字段不覆盖；旧端未知值保留原始数据 |
| Post／Entry | id、entryKind、rootPostId、replyToId、state、version、text、media bindings、language、anonymous | draftId、编辑光标、未提交附件 | 默认旧 POST 兼容；批准版本快照不可被后改媒体替换 |
| Letter | id、sender、recipient、version、deliveryState、withdrawnAt、双方隐藏状态 | 本人草稿、提交快照、确认中状态 | 指定双方权限；sender 等内部字段不直接用作公开 DTO |
| Media | id、owner、purpose、storageKey、mime、bytes、duration、sha256、processingState、version、expiresAt | encryptedFileId、uploadId、临时播放文件 | storageKey／访问密钥不出 DTO；绑定目标版本与用途 |
| Note extension | 既有版本正文＋mediaIds＋sourceAnchor＋drawingFormat/version | 编辑源本机草稿、冲突副本 | sourceAnchor 含 bookId/releaseId/chapterId/paragraphId/quoteHash；定位失败不猜测新位置 |
| OperationReceipt | owner、operationType、clientRequestId、payloadHash、state、resultType/Id/version | attempt、nextRetryAt、dispatchGeneration | 唯一 owner＋type＋key，写业务同事务；不复制正文 |

拟新增 `zf_client_operation` 只承接本专题操作幂等与结果查询，优先复用既有可满足同等语义的幂等设施；G01 核对后只保留一种实现。它与通知用的服务端 `zf_outbox`、客户端 `sync_operation` 是三种不同职责，不能混为一个队列。

园境协议示例为候选字段，不是运行返回：

```json
{
  "expectedVersion": 12,
  "clientRequestId": "op-example-001",
  "operations": [
    { "type": "SET_FISH_NAME", "instanceId": "fish-example-01", "name": "小白" },
    { "type": "SET_ENVIRONMENT", "presetId": "rain", "lampEnabled": true }
  ]
}
```

`operations` 为显式枚举：INIT、SET_FISH_NAME、SET_FISH_ARCHETYPE、UPSERT_PLACEMENT、REMOVE_PLACEMENT、SET_ENVIRONMENT。服务端事务内校验整批后一次加版本；任何一项失败整批不写。初建 `expectedVersion=0` 且仅允许 INIT，服务端生成初始鱼实例；游客导入 INIT 可携带允许园境选择与临时 ID 映射，仍须原子确认不存在。GET 不暗中创建园境。已存在返回当前版本冲突，不覆盖。

普通 PATCH 不传的领域保持原值；同一 patch 中有环境变化时才允许写环境字段。冲突响应可返回本人最新快照／版本，其他所有者仍为不可见。冲突解决生成基于新版本的新操作与新键，旧失败回执保持不变。

投稿新客户端至少传 `entryKind`、`language`、`anonymous`、`text`、`mediaIds`、`clientRequestId`；创建根签不允许客户端传任意 rootPostId。回应父 ID 来自路径，replyToId 必须属于同根且当前可访问。旧请求沿 title／text／category／attachmentIds，旧列表默认仅 POST；测试缺省字段、空数组及旧版本序列化。

## 4. 媒体与业务提交的事务边界

1. 本机确认操作后固定内容及目标，建立本机 sync_operation；媒体不变更用途。私人转公开需要新的 PUBLIC_SUBMISSION 登记与副本授权，不能复用 PRIVATE_NOTE 绑定。
2. 创建上传返回 `uploadId`、`mediaId`、`version`、`expiresAt`、允许 MIME／bytes／duration；客户端不能提高限制。整文件 PUT 允许同 uploadId 同 hash 重试，异内容返回冲突。
3. complete 幂等，服务端真实检测容器／时长／大小；status 返回 RECEIVING／PROCESSING／READY／FAILED／EXPIRED。未 READY 不允许业务引用。
4. 投稿／保存／寄信事务内检查媒体所有者、purpose、READY、未被不兼容目标绑定及父对象权限；落库内容版本、绑定、幂等回执与必要通知 outbox。
5. 返回内容 ID／version／state 才表示业务成功。上传完成但业务失败时保留可重试上下文；过期未绑定媒体清理，不伪造内容成功。
6. 播放 content 支持 Range；每个请求复验父对象和当前身份。审核音频走管理员受限端点，不把消费者链接转发给后台。撤回后新请求拒绝；已听见／截取内容无法收回。

原声暂定 60 秒和 5 MiB，取任一上限停止；图片／笔迹限制另用集中配置，不继承音频时长。客户端、网关和服务端统一使用同版本限制。一次仅上传一个大文件，避免多份 Base64／ArrayBuffer 并存。签名 URL 若以后引入，需重新评审有效期与撤回窗口，首版不预建旁路。

## 5. 幂等、错误与确认未知结果

对新建、发送及可重试写操作，客户端先持久化唯一 key 与规范化 payloadHash，再发送。JSON 中 clientRequestId 与 `Idempotency-Key` 同时出现时必须一致。hash 由服务端按约定字段规范化复算；不能只信客户端 hash。文件 hash 由服务端对真实内容校验。

回执 GET 返回 PROCESSING／SUCCEEDED／REJECTED，含 resultType／resultId／resultVersion 或 safeErrorCode。找不到用 404 OPERATION_NOT_FOUND，只表示未找到登记，不能据此判定“已经发送失败”；仍用原键、原内容重试，让唯一约束化解并发。业务提交和 SUCCEEDED 回执必须同事务。请求断线时界面显示“正在确认结果”，不生成新键。

幂等结果保留紧凑映射；目标删除后保留不含正文的已处理标记，不能删除映射后接受同键新建第二份。保留策略纳入账号删除／合规策略，客户端对已超服务端重试支持范围的旧操作停止自动重放并要求用户处理。既有 notes 的 clientRecordId、messages 的 clientMessageId 继续保留，不再生成平行业务对象；为需要离线对账的 note 写入补统一回执或等价可查询结果。旧接口未经补齐前，不纳入自动重试白名单。

| 类别 | 处理 |
| --- | --- |
| 401 | 既有 session 最多刷新并重试一次；失败暂停该所有者队列，保留锁定草稿 |
| 403／404 | 关系／权限失效或目标不可见：停止业务重试，保留本人的未发内容；不推测目标身份 |
| 409 VERSION_CONFLICT | 保留本地基线与服务器新版本，等待冲突解决；不自动最后写入覆盖 |
| 409 IDEMPOTENCY_CONFLICT | 同键内容变化，视为实现错误／非法操作，停止重试，不偷偷换键发送 |
| 413／422 | 超限、格式或状态不满足：显示可修正问题，修改后形成新提交，旧快照不覆盖 |
| 429 | 尊重 Retry-After，回到前台再调度；不连续弹提示或自动绕限流 |
| 5xx／断网／超时 | 写请求可能成功，先查回执，再同键重试；退避规则见存储文档 |
| 返回数据格式错误／旧身份回调 | 不当成功；保留诊断 ID，丢弃旧身份结果，不落入新库 |

## 6. 后台与数据生命周期对应

| 后台动作 | 接口／对象 | 约束 |
| --- | --- | --- |
| 查看投稿、审核 | E/X 管理前缀下 `GET /community/posts`、`POST /community/posts/{id}/review` | 新 kind 和音频扩展；校验版本、角色与提交快照 |
| 播放待审核音频 | N `GET /community/posts/{id}/media/{mediaId}/content` | 仅该提交绑定，不能读任意 mediaId |
| 举报工单 | N `GET /community/reports`、`GET /community/reports/{id}`、`POST /community/reports/{id}/decision` | 工单权限；所选证据包；变更传 expectedVersion 与幂等键 |
| 资源／媒体状态 | N 受限只读页面与统计端点，G10 定稿 | 无私人正文或音频预览；不建立在线建模平台 |
| 删除与清理 | 既有 worker／zf_outbox 扩展 eventType | 各 worker 按类型认领，防止旧笔记 worker 消费社交事件 |

撤回先改变服务端可见性，同事务记录清理事件，随后清理对象／派生稿／预览／索引；失败可重试。本人隐藏信件、作者撤回、移除朋友、屏蔽和删除账号各有语义，不复用一个 deleted 布尔值蒙混。移除朋友保留已送达历史的双方读取，屏蔽阻断关系下读取，解除屏蔽不恢复好友；撤回优先于历史读取。举报证据只按配置的受限期限保存，不给普通媒体端点访问。

## 7. G01 契约交付门槛

将上述 N／X 形成项目现有风格的 OpenAPI／TypeScript DTO 与服务端测试夹具；字段限制、分页游标、错误、版本和幂等示例一致。补充 gateway 允许方法／路径、消费者与管理员权限、请求大小／Range／取消处理。构造两个 APP_USER 加管理员的跨主体请求验证；测试上传后被屏蔽、根签撤回、重复请求、旧版 POST、无 AI 配置等竞争条件。

本文件只是可实施设计；接口存在须以源码和测试为准，真实运行须以对应环境联调为准。
