## 1. 已有能力与本次最小补充

源码现状：原生 `secure-session.ts` 将 refreshToken／scope／origin 存在 SecureStore；Web 实现将对应身份数据保存在 localStorage 并有多标签锁和事件。`session.ts` 恢复身份需要网络刷新与 profile 校验，没有已完成的冷启动离线认证。园境 `garden-files.ts` 主要缓存公共资源；部分编辑正文仍在组件状态。package.json 已有 expo-file-system、expo-secure-store、expo-crypto、expo-audio，没有 expo-sqlite／AsyncStorage。

建议只新增与当前 Expo SDK 57 匹配的 `expo-sqlite`，原生构建启用 SQLCipher，承接园境快照、草稿和重试队列的事务；复用现有 FileSystem 保存媒体、SecureStore 管理钥匙、expo-crypto 加密文件。现有凭据存储不适合大正文，普通文件也不能保证“草稿已存但队列没存”等多记录事务；因此不自行设计多文件 JSON 日志，也不再加第二个状态数据库。依赖版本在 G05 样板中锁定，禁止顺手升级 Expo。

SQLCipher 需要配置插件和重新构建原生 App，不能以 Expo Go 验证；Web SQLite 仍有独立限制，所以电脑浏览器使用同接口的内存／虚构数据适配器。iPad 模拟器必须验证实际原生实现，浏览器通过不等于本机加密通过。[Expo SDK 57 SQLite](https://docs.expo.dev/versions/v57.0.0/sdk/sqlite/)

现有 Web 登录凭据行为属于已存在代码；本方案不声称它等同原生 Keychain，也不借本任务重写整个 Web 认证。新增游戏私人草稿不进入 Web localStorage；浏览器开发只用虚构内容，生产 Web 私人离线能力另行设计。

## 2. 归属、目录与钥匙

逻辑 ownerKey 由规范化的部署 origin、environment、tenantId、APP_USER、userId 构成，字段使用稳定序列化，避免字符串分隔冲突。复用既有 identityScope 的含义，再加入 origin；不能只用邮箱、publicId、设备名或当前选择的演示用户名。磁盘目录使用 ownerKey 的摘要，摘要只减少明文身份暴露，不代替权限检查。

建议逻辑布局（最终系统目录由原生适配确定）：

```text
public-assets/<sceneVersion>/<packageHash>/    公共可重下包
public-books/<release>/<language>/             获准离线缓存的已发布正文
owners/<ownerDigest>/state.db                  SQLCipher 数据库
owners/<ownerDigest>/media/<randomFileId>.enc   私人媒体密文
owners/<ownerDigest>/staging/                  写入中的密文
volatile-private/<sessionId>/                 受系统保护的短期明文
secure-store: ownerDigest.dbKey / mediaKey / keyVersion
```

每账号独立随机数据库钥匙与媒体钥匙，不能从密码、userId 或固定常量推导。原生安全随机生成；不使用 Math.random。数据库创建后第一步设钥匙，任何 schema 查询之前验证 cipher 可用；错误钥匙或缺 cipher 必须失败，绝不降为明文 SQLite。所有查询使用绑定参数；钥匙只交原生存储适配，不进入日志、WebView、网络或状态调试快照。

数据库钥匙存 SecureStore，建议 iOS `WHEN_UNLOCKED_THIS_DEVICE_ONLY`；它约束锁屏读取和跨设备迁移，不等于 Invelle 账号认证，账号检查仍由 App 执行。锁屏、退出或切账号关闭连接并尽力释放内存钥匙，不声称 JavaScript 内存能做绝对安全擦除。不要为恢复草稿强制打开生物识别依赖。[Expo SecureStore](https://docs.expo.dev/versions/latest/sdk/securestore/)

DB、WAL、SHM、媒体、临时文件和崩溃恢复副本都要应用合适的 iOS 文件保护；建议私人内容采用解锁时访问，后台不写敏感数据。备份排除需原生属性实际核验，不能只凭目录名判断。SecureStore 在卸载／重装后的保留不能当可靠产品协议；安装标记消失时不得凭残留钥匙直接恢复登录。检测钥匙有而库无、库有而钥匙无的情况，明确提示本机草稿不可恢复，不反复建空库冒充成功。

## 3. 数据分层与保存授权

| 数据 | 权威来源／本机介质 | 保存／同步触发 | 淘汰／退出规则 |
| --- | --- | --- | --- |
| 公共模型、纹理、天气资源 | 资源清单／普通校验缓存 | 用户进入区域后下载 | LRU；保留当前与一个可回退版本的必要包 |
| 设备偏好 | 本机非敏感配置 | 音量、语言显示、质量、减少动态变更 | 不随账号上传或强迫另一设备改变 |
| 私人园境 | 服务端＋加密 base／working 快照 | 确认保存入本机并排队 | 退出锁定；仅可重建的云端缓存可清理 |
| 文字、笔迹、原声草稿 | 本人加密库＋文件 | 编辑防抖／停录后本机保存；保存云端需明确操作 | 未同步草稿不得按 LRU 自动删 |
| 本人已同步笔记 | 服务端权威；按需加密缓存 | 打开或本人选择保留 | 可清可重下；清缓存不得连带删未同步编辑 |
| 收到来信／公共愿签正文与音频 | 服务端当前可见性；内存／短期播放缓存 | 在线打开及播放 | 首版不提供跨会话离线收藏；离页／后台／退出清理 |
| 本人投稿／发送快照 | 加密队列临时保存 | 确认时固定 | 对账成功后清除提交副本，原私人笔记仍按其自身规则保留 |
| 阅读进度／书签 | 本机 owner 库；云端按原开关 | 用户明确开启同步后进入队列 | 关闭同步取消尚未派发项，不撤销已完成操作；清云端沿既有接口 |
| 聊天输入 | 本人本机草稿；会话在既有服务 | 编辑可存草稿，发送须在线确认 | 网络恢复不自动补发旧问题 |
| 临时纸 | 仅内存 | 无持久化 | 离开／后台销毁；不进恢复、索引、日志或备份 |
| refreshToken／密码／验证码 | token 沿 SecureStore；密码验证码只用认证流程 | 原身份组件 | 不进业务数据库／离线队列 |

“自动保存”只指本人本机草稿；不表示云端保存、长期记忆、公开投稿或发送给朋友。用户点击明确“保存到云端”才形成该操作授权。录音录到一半的系统临时文件是实现需要，不能宣称录制全程从未产生明文。

## 4. 本机 schema 与接口职责

每个所有者数据库建议如下；SQL 由 G05 按实际库版本编制，本文件不提供可直接执行的迁移。

| 表 | 主要字段 | 唯一／一致性规则 |
| --- | --- | --- |
| local_meta | schemaVersion、ownerKey、keyVersion、createdAt | 打开时与受信身份一致，否则拒绝 |
| garden_snapshot | gardenId、baseVersion、baseJson、workingJson、localRevision | base 为最后确认云端，working 为本机当前；不把待同步值覆盖 base |
| draft | draftId、kind、targetRef、sourceVersion、body、localRevision、persistedAt、status | 修改版本递增；用途区分 NOTE／WISH／LETTER／DRAWING／CHAT；不含临时纸 |
| local_media | fileId、draftId、purpose、relativePath、mime、bytes、sha256、keyVersion、state | 仅相对受限路径，禁止任意路径访问；每文件不可变内容 |
| sync_operation | operationId、type、targetRef、baseVersion、payload、payloadHash、clientRequestId、confirmedAt、state、attempt、nextRetryAt、lease、lastError | type＋key 唯一；不可变提交快照与依赖；没有确认的草稿不建发送操作 |
| sync_dependency | operationId、dependsOn | 媒体 READY 后方可提交目标；不得有环 |
| cached_entity | type、id、serverVersion、body、fetchedAt | 仅允许本人可缓存类型；无他人正文离线库 |
| reading_state | releaseId、chapterId、anchor、bookmarks、syncEnabled、localRevision | 按 owner 隔离；未启用不生成云端任务 |
| deletion_mark | objectType、id、requestedAt、operationId、state | 删除意图优先于旧下载；不得被迟到成功响应复活 |

一个进程每个活动账号只有一个 LocalStore 与 SyncCoordinator，应用层串行调度写事务，数据库唯一约束兜底。原生用排他事务把工作快照、操作及依赖一起提交；不要在事务中等待网络或长文件加密。通过 lease／启动代次识别进程崩溃遗留 RUNNING 项，先对账再恢复，不同时启动两个重放器。

建议 LocalStore 提供 openOwner／closeOwner、saveDraft、prepareOperation、applyReceipt、markConflict、discardDraft、clearRebuildableCache；领域模块不自行开数据库或访问路径。原生与浏览器适配遵守相同接口，浏览器实现明确标 DEMO，不承诺安全与持久性。

## 5. 草稿落盘、录音与文件原子性

文字建议空闲 500 ms 写入，持续输入每 2 秒最多间隔落盘一次；退出编辑、切换区域、显式保存前立即 flush。显示“已存本机”必须在事务成功后。若 OS 突然终止，恢复到最近成功落盘版本，尚未落盘的少量输入不作零丢失承诺。笔迹按增量或适度批次保存可编辑源，不每帧写大文件。

录音停止后封装原格式，计算大小／时长与 hash，在后台任务可用时间内加密到 staging，校验成功再原子重命名并登记 local_media，最后清除明文临时文件。数据库和文件系统不能共享一个事务：采用 STAGED → READY 登记流程，启动时清理无引用 staging，恢复有已完成文件但未登记的安全记录；无法匹配 owner 的明文临时文件只清理，不能猜测归属。

媒体采用现有 expo-crypto 的 AES-GCM 能力，随机 nonce、认证标签与 keyVersion 随文件封装，附加认证数据绑定 ownerDigest／fileId／purpose／formatVersion。每次加密生成新 nonce，不复用固定 IV；加密库失败不落普通明文替代。只处理受限小文件并测量峰值内存，超上限前停止；大文件不自行发明分块密码协议。[Expo SDK 57 Crypto](https://docs.expo.dev/versions/v57.0.0/sdk/crypto/)

播放与上传若原生库需要文件 URI，按需解密到受保护 volatile 目录，任务结束／后台／换号尽力删除，启动时清理残留。界面必须如实说明异常中断的录音可能不完整；损坏文件不可冒充正常可试听草稿。明文临时目录、持久私人库和 Keychain 均不允许 WebView 访问。

文件写入失败、磁盘不足或钥匙不可用时保留当前可用编辑状态并显示具体恢复选项；不得提示已保存后清空编辑器。允许用户选择明确导出或删除，但导出属于主动分享动作，不自动把私人文件写到公共下载目录。

## 6. 离线与账号生命周期

| 情境 | 本机读取／写入 | 网络队列 |
| --- | --- | --- |
| 本次已认证、前台断网 | 可编辑已解锁本人内容及缓存园境 | 已确认的园境／私人保存等待网络；投稿／来信按下节规则 |
| 同进程后台恢复，身份未改变 | 重新打开本人库；复核删除标记和会话代次 | 重新验证当前会话后才派发 |
| 无网冷启动 | 只开公共游客园景，私人库保持锁定；说明联网登录后恢复草稿 | 不用旧 refresh token 假定已认证，不发送 |
| 再次在线登录同一账号 | ownerKey 一致才可解锁旧库；显示本人待处理项 | 重新绑定新的 dispatchGeneration；不会沿旧代次直接继续 |
| 退出／换账号 | 立即遮盖，取消请求／录放音，关库并清会话临时文件；已落盘未发草稿加密锁定保留 | 暂停旧账号队列；B 不能查看／执行 A 的操作 |
| 明确“清除此账号本机数据” | 说明未同步数量，确认后删库／媒体／钥匙／WAL 等 | 撤销本机待派发；在途结果仍需服务端查询，不能声称远端撤回 |
| 账号删除已获服务端受理 | 关闭私人内容与新写入，清理本机资料 | 只保留删除作业必要凭证／状态；状态查询需服务端限定权限，不复用完整业务访问 |

无网冷启动锁定是沿现有在线恢复机制的 v1 默认值，不表示永不支持离线解锁。若要新增离线冷启动访问私人库，需要单独的设备本地认证、超时与失效规则；本版不通过静默放宽身份检查来实现。

退出前正在录音：先停止并尽力加密保存；失败明确提示未保存，用户可重试或放弃。强制切账号／会话撤销时隐私优先，旧内容不得继续展示；未封装录音可能丢失，不能为了保留它而把明文留给新会话。

## 7. 队列、重试与不可逆动作

```text
本机草稿 --明确保存/投稿/寄送--> PREPARED
PREPARED --> WAIT_DEPENDENCY --> READY --> IN_FLIGHT
IN_FLIGHT --> ACKED / UNKNOWN / RETRY_WAIT / CONFLICT / NEEDS_ACTION
UNKNOWN --> 查询同键回执 --> ACKED / RETRY_WAIT / NEEDS_ACTION
退出账号 --> PAUSED_OWNER；再次验证同账号后重新检查
```

自动重试白名单仅包含已完成幂等与回执支持的操作。园境确认保存、私人笔记确认云端保存、已开启的阅读同步可在同账号网络恢复后重试；未确认草稿不上传。好友接受／移除、屏蔽／解除、账号绑定／删除不通用排队，在线明确执行；未知结果先查询。

投稿／寄信必须点击当次确认。离线点击时保留本机草稿，提示“联网后再确认”，不预定日后自动发送；在线已确认且结果未知，只允许同键同内容对账／重试，不能更换接收者或附件。冷启动／重新登录后的未派发社交操作停在 NEEDS_ACTION，再确认后执行；已经派发的未知结果先查询原回执，不能把它当未发送另建一份。一次确认覆盖同一快照的技术性重试，不覆盖改写后的新内容。

媒体和目标写入依赖排序：先上传并确认 READY，再提交业务对象。网络恢复先校验身份及服务可用性，再按目标串行处理；不同账号绝不共用队列。建议退避 2、5、15、30、60 秒并加抖动；后台不持续唤醒重试，429 尊重服务端等待值。连续 5 次失败转 NEEDS_ACTION，保留内容并允许人工重试，不无限耗电。

用户取消：尚未派发可撤销操作并保留或删除草稿；已经在途不能保证服务端没执行，界面先“确认结果”，成功则提供既有撤回动作。网络 AbortController 只停止本机等待，不等于取消服务端事务。

## 8. 多设备冲突与删除优先

园境保存基于 baseVersion，客户端保留 base／working／服务端新版本三份。初版不自动做可能丢信息的合并：展示冲突领域及变化，可选“采用云端”或逐项保留本人改动；重新验证鱼实例、锚点和允许范围后，以新版本生成新操作。未知鱼型／摆件／天气保留原始值，运行显示降级不等于写回默认值。

笔记版本冲突保留本机副本与远端版本，可另存或明确覆盖选定修改；不可只改 expectedVersion 后盲重放。读书源版本变化时保留原锚点与摘句，不静默把批注绑到错误段落。

删除记录时本机立即置 deletion_mark 并隐藏，取消尚未派发编辑；网络删除回执确认后才清对应缓存与附件。迟到读取／旧保存回执不能复活已删对象。远端已删而本机有未同步草稿时，保留为未绑定冲突副本，提示用户决定另存，不自动重建原对象。账号删除或明确清本机数据优先于草稿恢复。

收到来信和公共内容在线展示，断网停止新获取；已有内存画面可短暂保留并标明离线，退出／后台即清。服务端撤回可以阻断新读取，无法保证抹除对方已看见、截屏或已缓冲内容，产品文案不得承诺远程彻底销毁。

## 9. 升级、容量与备份

本机 schemaVersion 与 sceneVersion、服务端 stateVersion、媒体 formatVersion 分开。每次迁移顺序固定，事务内升级；大文件格式迁移先写新密文、验证后换引用，保留原文件直到成功。失败保留原库并显示修复状态，不删库重建掩盖错误；客户端低于本机 schema 支持版本时拒绝写入，提示使用兼容版本。

密钥轮换采用新 keyVersion 和可恢复迁移标记，确认所有库／文件可读取后才移除旧钥匙；没有轮换需求不每次登录生成新钥匙。改密码不等于重加密本机所有草稿，仍先验证同一 APP_USER。失钥不能声称可恢复未同步资料；只恢复已在云端的数据，原密文等待用户确认清理。

容量初始建议：公共资源软预算 512 MiB、私人可重建缓存 128 MiB、未同步媒体软提示 100 MiB；这些是测试起点，G02／G05 根据实际资产与设备调整。先按 LRU 清公共旧包及可重建私人缓存，绝不自动删未同步草稿／队列／当前有效资源。无法腾出写入空间时停止新录音／下载并提示；记录实际可用空间与错误，不按固定预算假定磁盘充足。

首版本机私人库与草稿不做 iCloud／系统跨设备备份，原生层设置并核验排除属性；钥匙不跨设备迁移。云端仅保存已明确授权的数据，因此“已存本机”文案说明换机／卸载可能失去未同步内容。需要导出时由用户主动选择，导出不改变原授权。公共资源可重新下载，备份清单不包含 token 或私人明文。

## 10. 本机机制验收

| ID | 注入／操作 | 预期证据 |
| --- | --- | --- |
| L01 | 输入、落盘提示前后强杀、重开 | 只恢复最后成功版本；失败不假报已保存 |
| L02 | 草稿与队列事务中异常 | 两者一致提交或回滚，无无来源操作／漏保存 |
| L03 | 停录、加密、重命名、登记各阶段强杀 | 正确恢复已完成密文或清理孤儿，明文无跨会话泄露 |
| L04 | 写入成功但响应丢失、重复点击、重启 | 同 key 只有一份业务内容，可查原回执 |
| L05 | 两设备改同一鱼／环境／笔记 | 保留本机及云端版本，不盲覆盖 |
| L06 | 上传成功、目标提交失败／被屏蔽 | 无假寄出，按用途重试或保留草稿，孤儿最终清理 |
| L07 | A 退出登录 B，旧请求／下载／播放返回 | B 看不到 A 数据；A 队列不以 B 身份运行 |
| L08 | 无网冷启动、再登录 A、登录不同账号 | 私人库默认锁定；只在验证原 owner 后恢复 |
| L09 | 错钥匙、无 cipher、失钥、密文篡改 | 明确失败；无明文降级／空库替代／错误账号恢复 |
| L10 | 数据库／文件迁移途中失败与降级 App | 原数据保留；旧 App 不写不兼容 schema |

| L12 | 删除与迟到保存／下载竞争 | 删除标记不被覆盖，远端删除不被自动复活 |
| L13 | 阅读同步开／关、游客导入、未知字段 | 未授权数据不上云；导入不覆盖；未知值不被回退值覆盖 |
