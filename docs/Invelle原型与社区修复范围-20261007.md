# Invelle 原型、社区与对话修复范围

## 已确认范围

1. 原首页布局保留，增加入口进入现有庭院/打坐；不以三维页直接替换首页。
2. 语音复用原型柔和流动的光球、呼吸和涟漪，圆形裁剪消除方框。
3. 首页与打坐有缓慢云雾漂移，保持文字可读，尊重减少动态。
4. 已发布陪伴人格调整语气、解释侧重、日常启发；一般知识允许模型知识回答，知识库增强依据。人格不改变史实，不强行转成情绪练习，不伪造原文/出处。
5. 创作是公开图文社区，推荐/分类列表/详情/投稿与后台审核；私人记录独立。用户已同意明确投稿、审核后公开、作者撤回/管理员下架，先不扩展点赞/关注/评论。图片上传需文件校验、附件所有权与未使用附件清理。
6. 记录还原原型个人列表和书写界面，所有相关文字输入支持语音。
7. 聊天语音识别结束即填入问答框并自动发送；取消、空结果、迟到或重复结果不发送；创作/记录仅填草稿，不自动保存或公开。
8. 知识资料后台独立一级入口，复用衍智云的列表、文件管理、切片、编辑、删除能力与产品权限边界，不连接旧库/旧账号/旧密钥。
9. 原文引用有独立浅色底块、来源标题/章节和可用出处；连续对话累积上下文，最多 200k token，受模型真实窗口限制，输出预留计入预算。保留近期完整轮次；压缩旧对话时保留不确定性与来源，不把摘要当原文。

## 已确认：资料关联方式

采用同一资料管理后台、同一引用与发布快照体系，陪伴版本明确选择方式：

- 固定参考：少量短原文/思想提要每轮直接注入，无需嵌入模型；后台显示实际消耗，超预算阻止准备，不无声截掉资料。适合稳定的人格辅助资料。
- 检索参考：书籍/长文先切片，再检索相关片段；可选关键词或现有向量检索，均明确配置，不静默混用。
- 推荐固定短参考加长资料检索，而不是每次注入全部书籍。用户可以先只用固定参考，不依赖 RAG。

资料管理、关联策略、人格规则分开。取消使用/删除资料需明确影响已发布快照，撤销后不可继续引用；私人数据不自动转入公共资料。

## 验收顺序

先复现知识问答拒答并验证人格调整，再验证上下文/引用与资料后台；完成社区前后端及图片链路，统一恢复原型与动态效果；直接连接 ubuntu-sg 验证；最后签名安装新包进行手机验收。会员账单/支付仍仅保留设计。本轮不使用本地 Docker，不提交/推送未获单独授权的代码。
