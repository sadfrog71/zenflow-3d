## 产品与体验

- 对外英文品牌为 Invelle，中文为此间；Zenflow 保留为工程与兼容标识，不做全仓改名。面向海外，保留中英文，当前优先 iOS，Android 验收另列。
- 核心是情感梳理、自我了解、陪伴、安静停留、疗愈与激励、随缘努力。「禅」体现在觉察、面对、接纳与放下的日常体验，不要求宗教身份或知识。允许沉默、休息、没有成果和自然结束；不增加强制打卡、排行榜、情绪评分或依赖诱导。疗愈是产品价值表达，不承诺医疗效果。
- 保留休息、聊天、创作、记录四入口和克制的中式视觉。按最新修订保留原首页布局，通过入口进入庭院与打坐；云雾、光球和呼吸效果尊重减少动态设置，声音默认关闭，退出或进入后台停止。
- 陪伴温和、清醒、诚实，尊重现实边界与自主选择；不把 AI 包装成精神权威，不以宗教或灵性语言责怪受伤者，不强制每次做情绪练习。
- 知识问题先回答知识问题，允许使用模型的一般知识；人格调整语气与解释侧重，不改变事实。具体原文与出处需要真实依据，原创示例、转述和直接引文明确区分。
- 原型的演示作品、预写回答、浏览器存储、录音自动停止逻辑不迁入正式业务。配置缺失、能力关闭或请求失败时明确反馈，不显示虚假成功。

## 用户数据分析、积累与授权

持续理解用户是产品核心能力。设计和开发应让获准的对话、记录与反馈逐步帮助用户看见自己的感受、需求、反复关注的事与变化；不能每次对话都从零开始，也不能以「了解用户」为由无边界收集。

| 层次 | 用途与边界 |
| --- | --- |
| 原始聊天与记录 | 保存用户表达、时间和来源版本；本人可查看、修改适用内容或删除，是分析依据 |
| 会话摘要 | 保持当前对话连续性，压缩旧推理上下文；不替代原始记录，不自动升级为跨会话记忆 |
| 已授权长期记忆 | 保存用户愿意延续使用的事实、偏好、目标与重要经历；可查看、确认、纠正和撤回 |
| 阶段性分析与回顾 | 在另行获准的范围内观察主题、情感和目标变化，保留证据与反例；月度 / 年度机制仍按专题设计推进 |

- 分析区分「用户明确陈述」「观察到的模式」「模型推测」，保留来源、时间、内容版本、授权范围及不确定性。一次情绪不等于稳定人格，不从聊天直接下诊断或固定性格结论。
- 有关事实、偏好与记忆存在冲突时，优先采用用户最新明确纠正，保留可追溯来源；模型推测作为待确认候选，不能自证后再当事实反复强化。
- 历史使用按当前问题相关性、时效性和授权筛选；避免重复追问已知信息，也不突然提及与当前话题无关的敏感经历。不把全部历史无差别塞进每次请求。
- 数据积累应可追溯、可更正、可撤销；新增派生摘要、标签或索引前说明用途、最小必要数据和删除传播方式，复用既有账号、胶囊、记忆与来源体系。积累量不作为用户情感状态或产品价值的评分。

### 私人和公共边界

- 公共论坛、获准参考资料、陪伴 Skill 与默认模型统一维护；账号、聊天、私人创作、记录、原音、偏好和记忆按个人隔离。共享能力不等于共享聊天。
- 服务端使用受信的 `tenantId + subjectType + subjectId` 验证资源归属；区分 `APP_USER` 与 `ADMIN_USER`，相同数字 ID 不互认。子资源、SSE、异步任务和恢复流程都需复核，不能只靠前端过滤。
- 保存私人记录、当轮选入、跨会话记忆、社区投稿是不同动作。不得把私人内容自动用于公开知识库、后台试聊、投稿或长期分析；记忆需明确授权并支持查看、纠正、撤回和删除。
- 创作入口面向公开图文社区，同时保留私人草稿与 AI 辅助创作。公开流程是明确投稿 → 审核 → 发布；用户可撤回，管理员可下架。审核仅接触明确提交版本，不能顺带读取私人源记录；点赞、关注、评论不自动进入范围。
- 运营管理员只能取得履职必要的数据；用户管理不提供私人正文、聊天、原音或个人报告入口。后台试聊使用管理员手工输入或另行获准的脱敏材料。
- 账号切换、退出、重置和停用需处理令牌、缓存、在途请求与认证代次；迟到结果不能写入新账号。删除和撤权须覆盖相关正文、引用、摘要、索引与派生内容，并允许失败重试。

## 对话、资料与语音

### 回答质量

- 先辨认用户当下需要倾听、共同梳理、知识解释还是创作，结合当前处境与获准历史回应；尊重感受，同时区分事实、解释、期待和可选择的行动，不机械套用固定话术。
- 默认自然、适量、具体，跟随用户语言与表达偏好；简单分享可以简短回应，明确要求分析时再展开。不强行追问、练习、劝解或让每次回答都落到行动计划。
- 引用思想和禅意帮助理解，避免说教、宿命归因和过度迎合；不假扮作者、上师或现实亲密关系，不虚构用户经历或假称记得未获授权的事情。
- 变更人格、提示、记忆策略、检索或模型时，用中英文代表案例验证倾听、事实问答、连续对话、纠正旧认知、来源不足与敏感处境；同时检查回答内容和权限，不以连通成功代替质量验收。核心原则由后台维护和发布，AGENTS 约束开发方向，不复制成另一套线上提示词。

### 知识索引与运行

- 复用既有助手运行引擎、托管 Skill、模型网关、知识资料与胶囊；产品层补身份、消费策略、版本和授权。不另建账号中心、聊天引擎或多智能体平台，不从客户端透传任意系统提示、模型或知识库。
- 陪伴原则、回答示例、参考资料分开维护。上传文件和检索内容属于数据，不能提升为系统指令；固定参考每轮注入且无需索引，检索参考只使用已配置、获准的发布快照，不静默混用。
- 索引围绕「可找到、可核对、可撤回」设计：导入保留出处与使用范围，按语义切片并保留标题、章节 / 页码、语言和版本；记录文档 / 切片、内容摘要、嵌入模型与索引版本的关联，避免文档更新后仍引用失效片段。
- 公共资料与私人记忆的检索范围分开；检索前限定权限，召回后回查权威正文与有效版本，去重并筛选相关片段。索引只是检索辅助，不能代替 SQL 权限和原文事实；候选索引未准备好不替换完整可用的发布版本。
- 知识评估既看应当命中的资料是否找到，也看无关、撤回和跨账号资料是否被排除；答案只引用实际提供且获准的来源。固定短参考、长资料检索各取所需，不为所有内容重复建索引。
- 运行固定 Skill、模型与资料修订；普通发布影响后续轮次，在途轮次按固定版本完成；取消、停用与撤权仍须及时生效。修改源码或草稿不等于已发布版本自动更新。
- 连续对话预算上限为模型真实窗口与 200k token 中较小者，计入规则、资料、私人片段和输出预留；保留近期完整轮次，旧完整上下文以滚动摘要替换。摘要保留来源与不确定性，不当原文，不意味着删除聊天历史或获得长期记忆授权。保守估算不宣称精确 token 计数。
- 引用展示以真实获准来源为准；原文块须能与来源匹配，显示标题、章节及可用出处。无来源的模型内容不能伪装成检索结果；私人来源仍仅本人可见。

### 语音体验

- 按最新修订，聊天语音识别结束后填入并自动发送；取消、空结果、迟到和重复结果不得发送。创作与记录语音仅填草稿，不自动保存或公开。
- 即时语音输入与 P2 长录音记录分开。后者要求默认保留原音、用户主动转写、支持至少 3 分钟、分段与校对，前端不写死 60 秒或 3 分钟上限；已有语音输入不能作为原音保存和长录音验收证据。

## 工程复用与范围

| 目录 | 职责与边界 |
| --- | --- |
| `zenflow-backend/` | Java / Spring Boot 产品服务；业务入口在 `zenflow/zenflow-biz/`，必要框架适配须有范围 |
| `zenflow-mobile/` | Expo / React Native App；复用现有页面、状态、契约、原生能力和资源构建脚本 |
| `zenflow-admin/` | Vue / Element Plus 运营后台；模型、陪伴、资料、示例、社区审核和必要用户管理 |
| `docs/`、`deploy/` | 设计、契约、状态、证据索引与独立部署文件 |
| `references/matrix/`、`prototype/` | 本机只读参考与已确认原型，不修改上游或用参考环境承载产品业务 |
| `.local-runtime/` | 本机临时产物与私密运行材料，不纳入产品仓库或公开交付 |

- 当前是一个根产品仓库内的三个工程目录，操作前仍以实际 Git 根目录核验；不按早期「三个独立仓库」建议重新拆库。依赖版本以现有配置和锁文件为准，不顺手升级。
- 复用衍智云时先查 [框架复用核查](框架复用核查.md)和实际模块，依次采用直接复用、产品门面 / 策略适配、必要新增。新增前说明原能力缺口；保留上游来源与兼容边界，不全仓改名或为一个产品改坏其他消费者。
- 移动端优先降低表达负担：键盘不遮挡输入，语音 / 文字切换保留草稿，返回与中断可恢复，加载和错误状态可理解；关注小屏、长文本、触控区域、前后台、弱网和动态效果开销。页面变化需在实际组件和目标设备核对，不只看浏览器截图。
- P0–P5 是设计分期索引，不是当前完成状态，也不限制后续明确批准的局部功能。九项修订与第 11 项资料 / 示例入口已有接续记录；本次任务仍按当前授权选择范围。
- 会员、试用、账单、支付和个人积累 / 年度回顾仍仅设计；不因存在表、菜单或方案就实现或启用。完整 CMS、社区治理、持久音频及 Android 等未验收部分按实际任务列出，不用局部交付宣称全部完成。
- 原型、参考源码和早期需求材料可能被 Git 忽略；新环境缺少时先检查已交付基线或说明缺口，不用猜测页面或静默生成替代设计。构建依赖这些文件时明确可复现条件。

### 未来会员体系

- 当前只保留扩展方向，不开发或启用收费。会员与个人身份、私人内容归属分离，继续关联同一 `app_user`，不另建一套会员用户；未来权益由服务端统一判断，App 与后台展示同一结果。
- 方案、权益、订单 / 账单、支付事件分别建模；订单保留方案快照，事件去重并可审计。旧框架 `pay_*` 仅作复用参考，不能直接视为完整会员体系。
- 试用天数、价格、额度、渠道、续费、退款均待确认；「10 天」仍是候选，不写死到注册或聊天逻辑。当前开发避免把未来权益判断散落到各页面，也不为预留而提前增加未使用的表和服务。
- 会员身份不扩大私人数据授权，个人分析与记忆开关不因付费自动开启。接入支付前再核对当时渠道和商店规则，单独完成资金与权益验证。

## 验证与交付

- 修改前明确影响的工程和完成条件；修改后执行相应子目录要求的定向检查。纯文档修改检查链接、路径、规则一致性和 Git 可见性，无需业务全量构建。
- 报告分别标注设计 / 原型、静态与单元测试、受控联调、真实提供方、浏览器 / 模拟器、真机、部署与用户验收，并使用 `PASS`、`PARTIAL`、`BLOCKED` 或 `FAIL`。给出实际范围、版本 / 构建和证据位置，不拼接不同版本的通过计数。
- 关键验证覆盖账号切换与跨主体拒绝、SSE 取消与断流恢复、幂等与版本冲突、来源撤销、社区公开范围，以及中英文和移动端键盘 / 语音交互；只运行本次变化相关项，再按发现扩大。
- 部署、数据库迁移、真实模型 / 陪伴发布、真机安装和 Git 推送按当前会话授权执行；状态文档的历史授权不代替本次授权。授权已覆盖的工作不重复确认。

## 服务端

### 代码与复用

- 产品业务在 `zenflow/zenflow-biz/`，单体装配在 `matrix-boot/`。复用认证、账号、RBAC、助手、托管 Skill、胶囊、模型与知识资料；框架通过策略和端口接入产品，避免反向依赖产品实现或形成循环。
- 旧框架模块存在不等于已开放。新增或调整接口须一起检查 `ZenflowEndpointBoundaryFilter`、认证 / 权限配置和 `../deploy/ubuntu-sg/gateway.mjs`；App、后台路径按 v0.3 映射，不放开企业接口或私人文件旁路。
- Controller 处理输入与身份，Service 处理事务，数据访问带租户、主体、所有者与状态约束。运行、消息、引用、附件等子对象回查父资源，异步任务携带原始身份和有效授权。

### 关键实现约束

- 消费者 `APP_USER` 与管理员 `ADMIN_USER` 隔离；`auth_version` 覆盖请求、刷新、SSE 和在途任务。第三方登录复用原账号中心、授权码与 PKCE，不因相同邮箱自动合并账号，不信任客户端自报身份。
- 对话沿既有 Assistant / Managed Skill / Model Gateway 执行；保持固定修订、幂等、取消、事件序号、断流快照和先持久化后完成的约束。普通发布与紧急撤权分别处理，不删除全局复核来放行某个产品。
- 资料区分固定注入与检索，使用获准快照。向量结果必须回查 SQL 中的归属、版本和撤回状态；无索引不阻止合法固定参考，缺配置不静默换模型或存储。继承的 `matrix-knowledge/AGENTS.md` 仅指导框架内部实现。
- 上下文压缩遵循本文「对话、资料与语音」的窗口和输出预算；摘要缓存复核身份、认证代次、来源授权与历史 lineage，不重复注入已被摘要替换的旧完整上下文，不扩大私人数据用途。
- 用户分析沿原始记录 → 会话摘要 → 获准记忆 / 回顾的分层设计，保存证据、时间、版本与用途授权，区分事实和推测。优先复用胶囊、记忆和来源服务；新增分析机制按已确认设计实施，不把本次规则整理视为年度回顾开发授权。
- 知识索引保留文档、切片、出处、语言、内容版本和嵌入配置关系；测试相关召回与越权排除、更新重建与撤回失效。公共索引和私人来源不能互相兜用，不以向量命中代替权威正文复核。
- 社区独立投稿、附件、审核与公开投影；检验文件类型、大小、归属和未使用附件清理。私人源记录不能经公开查询或后台审核旁路暴露。
- 原音、文字、记忆、引用、摘要和索引的删除 / 撤权保持一致；复用事务与 outbox 重试。凭据仅来自产品独立配置，缺失明确失败，不记录私人正文、密码、验证码、Token 或密钥。
- 未来会员复用 `app_user` 与现有权限设施，通过产品权益门面集中判断；当前不启用旧支付 Controller，不新增未经确认的试用 / 收费规则或空置会员体系。

### 数据与验证

- `db/zenflow/` 保存实际基线和分期迁移；先查目标库已有批次，再决定新增或补执行。已有库不能重跑空库初始化，已应用迁移不就地改写来代替新迁移；设计 DDL 不能直接整体执行。
- 编译和定向测试从本目录运行，按改动选择已有测试类；不要仅重跑 README 中的早期邮箱测试代表全部核心功能。示例：

## 移动端

### 目录与身份

- `src/app/` 组装入口；`src/contracts/zenflow/` 放契约；`src/core/zenflow/` 放 API、账号与业务状态；`src/platform/zenflow/` 放安全存储；`src/features/zenflow/` 放产品交互；`modules/invelle-speech/` 放本机语音桥接。
- 仅连接此间专用 HTTPS 网关；路径不能重复叠加 `/admin`，缺配置明确提示，不回退旧产品服务。海外登录复用现有 Google、Facebook、Apple 和邮箱适配，不另建账号状态体系。
- 邮箱密码在服务端认证页输入；授权码配合 PKCE，access token 留在内存，SecureStore 只存 refresh token，不持久化提供方访问令牌或私密 secret。
- 切换账号前终止旧 SSE 与异步操作，处理录音 / 草稿归属并清理私人视图；迟到请求、语音结果、上传和离线队列不能以新身份回放。取消登录不当作账号创建成功。

### 页面与交互

- 书籍中英文阅读及后续上架统一遵循 [阅读版本排版规范](books/阅读版本排版规范.md)：英文正文不附中文底本，词句释义与章节解读使用英文，夹注布局参照中文版。

- 保留休息、聊天、创作、记录四入口。最新首页布局与进入庭院的规则优先于 build9 中直接以三维页做首页的旧说明；保留原庭院相机、打坐、起身和声音交互，不自行换成另一套视觉。
- 复用 `scripts/zenflow/build-home.cjs`、`build-garden.cjs`、`build-voice.cjs` 及其源素材；`src/features/zenflow/*-source.json` 是生成物。先改源，再生成并检查差异，不能只改生成物。脚本依赖本机 `../prototype/`，缺失时明确说明，不悄悄改用替代资源。
- 本机 WebView 使用已打包资源与内容指纹更新，不能永久复用旧 HTML 缓存；核查安全区域、键盘、导航隐藏恢复和文件资源访问。声音默认关闭，离开 / 后台停止，首页和庭院均响应减少动态。
- 创作社区与私人草稿区分；投稿前明确公开范围，语音与 AI 候选只写草稿，保存或投稿由用户选择。记录列表、原文、收藏 / 置顶 / 归档、授权和删除沿本人真实 API，不换成演示数据；置顶独立于收藏并优先显示。
- 聊天语音识别结束后自动填入并发送一次；取消、空结果、重复和旧会话迟到结果不发送。创作、记录及其标题 / 正文仅填入，不自动保存。沿现有会话代次与取消逻辑实现，避免页面各写一套。
- 即时语音输入不代表原录音保存或 P2 长音频已完成。系统权限、真实识别和 Android 支持分别验证；不支持时明确反馈。
- 聊天沿真实 SSE、取消与快照恢复；不把断流当完成。引用只呈现有权限的真实来源，原文块遵守来源校验。中英文、长文本、键盘避让与光球圆形裁剪均按目标设备检查。
- 陪伴体验支持接续已获准的经历与偏好，避免反复让用户重新介绍；记忆使用、纠正、撤回和私人 / 公开选择应可理解、可操作，不把分析标签冒充确定人格。年度回顾仍是后续设计，不做假报告入口。

## 管理后台

### 目录与复用

- 沿用 Vue 3、Element Plus、Pinia 和现有锁文件；页面在 `src/views/zenflow/`，请求在 `src/api/zenflow/client.ts`，管理员状态在 `src/stores/identity.ts`，导航在 `src/App.vue`。基于实际结构修改，不为迎合早期设计目录另造一套后台。
- 后台经产品网关访问管理 API，不在浏览器直连模型供应商、数据库或旧 MATRIX 环境。缺少能力 / 配置明确显示，不伪造发布、测试或保存成功。

### 业务与权限

- 模型、陪伴、资料、示例、社区审核、用户与运行诊断各有职责。资料是独立一级入口，回答示例直接展示已有内容；复用既有列表、文件导入、切片编辑 / 删除与发布快照体系。
- 陪伴原则、固定参考、检索参考和回答示例分开配置。固定参考无需嵌入模型；检索参考明确配置与索引状态。草稿、准备、试聊、发布与回滚状态如实呈现，未发布的修改不冒充当前生效内容。
- 试聊与比较走真实服务端预览运行，只使用手工测试上下文和获准公共参考，不抽样消费者聊天或日记。展示实际版本、结果与来源，不展示内部思维链或模型密钥。
- 模型密钥只提交给专用服务端，不回显、不写浏览器持久存储或日志；保留用户已有模型参数。连通测试、激活模型和发布陪伴是不同动作，明确各自影响与失败状态。
- 用户管理展示必要账号元数据和状态，不能增加私人正文、原音、聊天或个人报告入口。消费者与管理员不能因数字 ID 相同互相访问。
- 知识管理显示资料来源、使用范围、切片与版本、索引状态及失败原因；更换资料或嵌入配置后明确重建 / 准备状态，不把上传成功等同于可检索或已发布。
- 个人积累功能的运营视图限必要任务状态与聚合信息，不为分析效果开放私人内容。未来会员管理沿根规则复用账号、集中展示权益和审计；价格、试用、支付渠道未确认前不实现收费流程。
- 社区仅审核明确提交的稿件与归属正确的附件；通过后公开，支持退回、撤回与下架。私人源记录和未提交草稿不进入审核列表；不擅自扩展点赞、关注、评论。
- 取消、断流、失败及部分回答按实际状态显示，迟到 SSE 不能覆盖新的试聊。并发编辑 / 发布带版本检查；过期状态须提示冲突，不静默覆盖。内容删除或撤销需显示对已发布来源的影响。
