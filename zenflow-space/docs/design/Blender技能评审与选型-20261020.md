# Blender 技能评审与选型

日期：2026-10-20。范围：现有候选与本项目美学、制作流程、文件操作的适配性。

制作顺序已更新到[设计总纲的 Blender 实施方案](禅意空间-设计总纲-v1.2-Blender制作版-20261020.md)。本文件保留技能选型与审阅证据；尺寸、功能与制作关卡以总纲最新正文为准。

**结论：主技能选择 `arjun988/blender-skills` 的 `environment-artist`，搭配同仓库的 `set-dressing`。材质和灯光技能仅按需引用配方，不作为整套自动制作流程执行。**

本次仅审阅与选型，没有安装技能、启用 MCP、执行候选脚本或修改 Blender 场景。当前效果图仍由内置 imagegen 编辑。

## 1. 为什么这样选

本项目首先需要的是「可实际搭建的院落＋坐姿构图＋少量生活物件」，其次才是材质配方。environment-artist 的模块库、前中后景、实例化、尺度与通路检查直接覆盖第一项；set-dressing 的空间叙事与密度控制覆盖第二项。两者不是东方美学专家，必须由设计总纲覆盖其默认值。

不按安装量给美学能力排名。社区关注度只能说明可见度，不能证明会做出这套空间。

| 候选 | 对本项目的价值 | 发现的问题 | 结论 |
| --- | --- | --- | --- |
| environment-artist | 建筑模块、院落、景观、构图、实例化、优化 | 默认站立视角 1.6 米；默认 2／4 米网格；强调游戏关注点 | **主技能，适配后使用** |
| set-dressing | 旧纸、杯碗、蒲团等物件表达生活痕迹，保持路径清楚 | 默认每组 3–7 件道具；例子偏离场、损坏和悬念 | **辅助技能，减少数量并改写叙事方向** |
| minimalist-style | 少色、少形、有意识留白 | 主文只有五条简短原则，附文仅一句减法规则；要求先删倒角，可能损失木石细腻的边缘受光 | 不作为主技能，现有总纲更具体 |
| arjun988 的 lighting | 灯光命名、分组、基本方向 | 配套含近黑月夜、恐怖高反差、较强闪烁，不符合暗部可辨与低刺激 | 不用整套风格规则 |
| RobLe3 的 blender-materials | 提供可检查的 PBR 与木纹、织物等代码配方 | 文内规则与例子不完全一致；配方不能直接等于已验证导出能力 | **保留为按需技术参考** |
| RobLe3 的 blender-lighting | 有窗光与场景实际灯具的配方 | 示例会删旧灯或清空 World 节点；默认多为三点摄影光 | **保留局部方法，禁止原样批量执行** |
| reference-to-3d | 正交轮廓、指定物件、参考与渲染比较 | 主要针对角色、标志与纹理模板；输入和验证方式不适用于当前完整院落效果图 | 当前不选，后续单件道具可再评 |

## 2. 必须覆盖的项目规则

使用 environment-artist 前，工作指令需明确以下覆盖项，不另建一套与总纲竞争的美术系统：

1. 采用总纲的 0.9／1.8／3.6 米模块关系，不能自动套用 2／4 米建筑网格。
2. 默认廊下坐姿先用 1.05 米，抄经厅约 0.65 米，阅读低案约 0.85 米；各处按总纲 §8.9 独立验证，不以统一站姿巡游镜头验收。
3. 庭院直达右前抄经厅，左前阅读厅的书架不位于必经路径；只做授权范围内的空间。
4. 观看态采用偏置主体和实体围合的留白，抄写态另设相机；不用目标标志引导视线。
5. 少量生活痕迹，不用全面污渍、破损、荒草表达「有人用过」。
6. 木石保留必要倒角与受光细节；低视觉密度不等于低模积木感。
7. 夜景至少辨清门、柱、席等暗部层次；禁用恐怖黑场、强闪烁、全屏雾和夸张轮廓光。
8. 杯碗、纸、灯和鸟可独立识别及替换，不能全部合并成一个不可编辑网格。
9. 不自动下载生成式三维资产，不因技能提到服务便发送项目文件或申请密钥。
10. 单一主 `.blend`、分集合、保存工作副本；任何删除节点、灯或对象的示例先改成只操作本次集合。

这些是后续使用约束，本次未修改任何已安装 Skill。

## 3. 代码和规则的具体发现

### 3.1 灯光配方会改变已有状态

RobLe3 `blender-lighting/SKILL.md` 的 `apply_three_point` 会按 `LGT-key`、`LGT-fill`、`LGT-rim` 前缀删除已有灯；实际灯具和 HDRI 配方会遍历并清空整个 World 节点树。示例用于新场景有一定合理性，但在已经有日夜灯光的项目里直接运行会覆盖原成果。

处理：仅在场景副本或本次专属集合中使用；复制 World 后再改；先记录现有节点、灯光与渲染设置。技能本身不是恶意，但示例的写入范围不符合本项目定向修改要求。

[源文：blender-lighting](https://github.com/RobLe3/cc-blender-skill/blob/a2634b588e80265e796aa53f8ab178d75105c2af/plugin/skills/blender-lighting/SKILL.md)

### 3.2 材质规则不能照单全收

`blender-materials` 开头要求只用 Principled BSDF，后面又提供删除它并换成独立 Emission 节点的示例；关于 Metallic 的绝对规则与后续部分混合材质说明也并不一致。附文还有待完善的烘焙导出清单。

处理：将其视为配方库，逐个核验实际 Blender 版本、材质节点和目标导出格式；不把「主文写了可导出」当成测试结果。纸张透光、油灯、旧铜和水面仍要单独做小样。

[源文：blender-materials](https://github.com/RobLe3/cc-blender-skill/blob/a2634b588e80265e796aa53f8ab178d75105c2af/plugin/skills/blender-materials/SKILL.md)

### 3.3 图像相似度脚本可能产生无意义的高分

`reference-to-3d/scripts/silhouette_validator.py` 对带 Alpha 的图片直接将 Alpha 转成轮廓。若参考图与渲染图都是全不透明 RGBA，两张图都会被视为整幅矩形；内容即使完全不同，也可能得到 IoU 为 1 的结果。对非 Alpha 图片，固定亮度阈值也可能把整个明亮背景当成对象。

这是源码推导的输入条件风险，本次没有运行该脚本。它需要准备正确的对象蒙版，不能直接给院落效果图打「还原度 95%」。

另外，其 `evals.json` 主要测试何时触发技能，不是渲染质量或资产正确性的测试证据。

[源文：轮廓验证脚本](https://github.com/RobLe3/cc-blender-skill/blob/a2634b588e80265e796aa53f8ab178d75105c2af/plugin/skills/reference-to-3d/scripts/silhouette_validator.py)

### 3.4 技能包不是可直接照搬的 Mac 连接配置

arjun988 仓库根 `.mcp.json` 使用 `cmd /c uvx ...`，属于 Windows 命令形式；同时引用的 `blender-mcp` 未锁版本。不能把该配置直接复制到当前 Mac。环境与布景叶子技能本身是 Markdown 指南，不包含完整建模程序；仍需独立验证 Blender 和连接层。

RobLe3 的后端说明明确存在不同连接实现和不同协议，要求先选后端、查询场景、避免超时后重放写入。这些保护原则有价值，但不能代替对实际连接软件的代码审查。

[源文：连接配置](https://github.com/arjun988/blender-skills/blob/8f778d2405a214b508d4c7d80742be8e43acdd52/.mcp.json)

## 5. 最终组合

**概念图局部修订：imagegen。** 用已确认的原图做局部编辑，保持空间识别；当前图稿已足够进入灰模，不要求继续补齐所有角落的效果图。

**Blender 制作指导：environment-artist 为主，set-dressing 为辅。** 按最新总纲分四期交付：全园灰模与空间定稿、核心样板与导出验证、全园完善与状态制作、整体验证与移交。第二期先验证导出，再精做临水廊下、水园近岸、读经厅及抄经厅暖暗样板；每期按总纲 §9.2 留下可复查证据。材质、灯光只按具体问题选取配方，缩小修改范围并验证。候选技能未安装不阻塞使用 Blender 自身功能或可审阅的本地脚本。

**暂不采用：minimalist-style 作为主技能、reference-to-3d 整院还原、Three.js 技能替代 Blender。** 不为技能覆盖面而同时安装两套总控流程，也不新造一套与设计总纲重复的美学 Skill。
